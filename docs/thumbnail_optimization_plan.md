# 缩略图加载优化专题 - 行动计划文档

## 概述

本文档描述了缩略图加载性能优化的完整行动计划，旨在解决缩略图加载时的卡顿问题，提升用户体验。

---

## 已完成的优化措施

### 1. 优化线程池和并发控制

**问题描述**：
- 原实现使用 `QThreadPool`，但任务提交和调度机制不够高效
- 线程数过多导致CPU竞争，造成UI卡顿
- 缺乏对运行任务数的有效控制

**优化措施**：
- 限制最大线程数为4，避免过多线程竞争CPU
- 添加运行任务计数器 (`_running_tasks`)，防止任务堆积
- 实现任务包装器 (`_wrap_runnable`)，跟踪任务运行状态
- 调度器检查当前运行任务数，超过阈值时暂停分发新任务

**代码变更**：
- 文件：`ui/utils/thumbnail_loader.py`
- 类：`ThumbnailLoader`

**预期效果**：
- 减少CPU竞争，提升UI响应性
- 避免任务堆积导致的内存压力

---

### 2. 实现智能优先级调度

**问题描述**：
- 原优先级系统简单，没有区分"立即可见"和"预加载"的优先级差异
- 所有任务使用单一队列，重要任务可能被延迟

**优化措施**：
- 实现双队列系统：
  - 高优先级队列：优先级 ≤ 0
  - 普通队列：优先级 > 0
- 定义优先级常量：
  - `PRIORITY_IMMEDIATE = -2`：立即可见区域，最高优先级
  - `PRIORITY_VISIBLE = -1`：可见区域
  - `PRIORITY_ADJACENT = 0`：相邻区域（预加载）
  - `PRIORITY_PRELOAD = 1`：预加载区域
  - `PRIORITY_BACKGROUND = 2`：后台加载
- 调度器优先从高优先级队列获取任务

**代码变更**：
- 文件：`ui/utils/thumbnail_loader.py`
- 方法：`_dispatch_loop()`, `load_thumbnails()`

**预期效果**：
- 可见区域缩略图优先加载，用户能更快看到内容
- 预加载任务不会阻塞重要任务

---

### 3. 优化UI响应性能

**问题描述**：
- `_load_visible_thumbnails` 遍历所有可见缩略图时可能阻塞UI
- 大模式下的预加载逻辑复杂，循环开销大

**优化措施**：
- 限制每次处理的最大缩略图数量为100个
- 优先处理可见区域，超出限制时截断处理范围
- 简化大模式下的预加载逻辑：
  - 原实现：遍历多个缩略图检查加载状态
  - 新实现：只检查第一个缩略图是否已加载
- 添加批量入队，减少锁竞争

**代码变更**：
- 文件：`ui/image_library_page.py`
- 方法：`_load_visible_thumbnails()`

**预期效果**：
- 减少单次调用的执行时间，避免阻塞UI
- 降低CPU占用，提升滚动流畅度

---

### 4. 优化滚动触发频率

**问题描述**：
- 滚动时使用固定的40ms延迟，不够灵活
- 快速滚动时频繁触发加载，造成资源浪费

**优化措施**：
- 实现自适应延迟机制：
  - 立即加载：`0ms`
  - 快速滚动时：`100ms`（增加延迟，避免频繁加载）
  - 鼠标忙碌时：`60ms`（如拖拽操作）
  - 正常情况：`40ms`
- 优化定时器管理：
  - 非立即加载请求，如果定时器已在运行，不再重新调度
  - 减少不必要的取消和重启操作

**代码变更**：
- 文件：`ui/image_library_page.py`
- 方法：`_schedule_visible_load()`

**预期效果**：
- 快速滚动时减少不必要的加载请求
- 静止时快速响应，提升用户体验

---

### 5. 批量处理优化

**问题描述**：
- 原实现逐个提交任务，锁竞争激烈
- 频繁的队列操作增加开销

**优化措施**：
- 批量收集任务，一次性入队
- 减少锁的获取和释放次数
- 使用临时列表存储待入队任务

**代码变更**：
- 文件：`ui/utils/thumbnail_loader.py`
- 方法：`load_thumbnails()`

**预期效果**：
- 减少锁竞争，提升并发性能
- 降低任务提交的开销
