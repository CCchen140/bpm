# 拍鸟日记功能 —— 需求设计文档

> 版本: v1.0  
> 日期: 2026-03-24  
> 状态: 需求设计阶段

---

## 1. 功能概述

**拍鸟日记** 根据用户已导入到图库的照片数据，按拍摄日期自动生成结构化的观鸟日记。每篇日记汇总当天的拍摄时间、地点、鸟种、数量、加新记录、最佳照片等信息，以书籍翻页的视觉风格展示。支持自定义日记模板、导出 Word、手动编辑，以及在设置中关闭自动生成。

---

#### 3.3.1 仪表盘区域（上半部分）

- 四周有圆角边框，背景色跟随主题
- 每个有日记的日期在仪表盘中用**一条竖线**表示
- 竖线宽度固定（约 3-4px），**高度与当天拍摄图片数量成正比**
  - 最低高度：仪表盘高度的 20%（保证可见可点击）
  - 最高高度：仪表盘高度的 95%（不超出上边缘）
  - 映射公式：`height = min_h + (max_h - min_h) * min(1, count / max_count_in_range)`
- 竖线从底部对齐向上生长
- 竖线下方显示对应日期标签（仅显示关键日期，避免拥挤）
- 鼠标悬浮在竖线上时显示 tooltip：`"2026-03-20 | 42张 | 18种"`
- 点击竖线 → 下方日记内容区滚动到对应日期

#### 3.3.2 时间轴滑动条（下半部分）

- 位于仪表盘下方
- 一条水平线，中间一个**圆点**作为拖拽手柄
- 拖拽圆点可平滑滚动仪表盘显示的时间范围
- 左右两侧各有 `[◀]` `[▶]` 按钮，点击快速切换到上/下一个时间段
- 时间段粒度：自动根据日记总跨度选择（< 3个月按周，< 1年按月，> 1年按季）

### 3.4 日记卡片设计

每篇日记呈现为一张"纸页"，具体视觉元素：

#### 3.4.1 装订线

- 页面左侧 **40px** 处有一条**竖直线**，贯穿整个日记内容区
- 颜色：主题 `theme.primary` 的 30% 透明度
- 宽度：2px，实线

#### 3.4.2 日记起始标记

- 每篇日记开头，在装订线上显示一个**双层圆**
- 外圆：直径 20px，主题 `theme.primary` 描边 2px，填充透明
- 内圆：直径 10px，主题 `theme.primary` 实心填充
- 日期文字在双层圆右侧，大字号加粗显示

#### 3.4.3 日记间隔

- 每篇日记卡片之间间隔 **40px**
- 不显示任何分隔线，深色背景自然作为视觉分隔
- 卡片带微阴影（`QGraphicsDropShadowEffect`：offset 0,2px，blur 8px，颜色 `#00000033`）增强纸张浮起感

## 4. 核心功能模块

### 4.1 日记内容生成

#### 4.1.1 数据源

从 `bird_results` 表查询，按 `shot_time` 的日期分组：

```sql
SELECT
    file_path, file_name, shot_time, location, latitude, longitude,
    object, species_cls, order_cls, family_cls, genus_cls,
    score, norm_score, focus_detect_json,
    fnumber, shutter, iso, focal_length, focus_distance,
    camera_model, lens_model
FROM bird_results
WHERE shot_time IS NOT NULL AND shot_time != ''
ORDER BY shot_time ASC
```

#### 4.1.2 日期分组

按 `shot_time` 的 **日期部分**（`YYYY-MM-DD`）分组，每个日期生成一篇日记。

#### 4.1.3 记录时间

- **起始时间**：当天拍摄时间最早的照片的 `shot_time`
- **结束时间**：当天拍摄时间最晚的照片的 `shot_time`
- 格式化为 `HH:MM - HH:MM`，如果起止相同则只显示一个时间

#### 4.1.4 拍鸟地点（智能聚合）

从当天所有照片的 `location` 字段提取地点，需要**智能识别**同一地方的不同表述。

**聚合算法**：

```
输入: 当天所有照片的 (location, latitude, longitude) 列表
输出: 聚合后的地点组列表

步骤:
1. 经纬度聚类（优先）:
   - 对有经纬度的照片，使用简易聚类（距离阈值 500m）
   - 同一簇内的照片归为同一地点
   - 簇的地点名取该簇中最短的 location 文本（去掉精确到门牌号的细节）

2. 文本相似度聚类（兜底）:
   - 对无经纬度但有 location 文本的照片，做文本相似度聚类
   - 提取地点核心词：去除方位词（东/西/南/北/左/右/旁/对面/附近）和距离描述（xxx米）
   - 核心词相同的归为同一地点
   
3. 合并两种聚类结果:
   - 如果经纬度簇和文本簇的核心地名重叠，合并
```

**相似度判定规则**（文本聚类细节）：

| 场景 | 文本A | 文本B | 判定 |
|------|-------|-------|------|
| 方位词差异 | 南京市绿水湾湿地大门 | 南京市绿水湾湿地大门左一百米 | ✅ 同一地点 |
| 精确度差异 | 南京市绿水湾湿地公园 | 绿水湾湿地 | ✅ 同一地点 |
| 完全不同 | 南京市绿水湾湿地 | 南京市玄武湖公园 | ❌ 不同地点 |
| 同城不同景区 | 南京市紫金山 | 南京市玄武湖 | ❌ 不同地点 |

**核心词提取**：
- 去除省/市/区前缀（可选保留）
- 去除方位后缀：正则 `(东|西|南|北|左|右|旁|对面|附近|门口|入口|出口|停车场)[\d]*[米千公里]*$`
- 去除距离描述：正则 `[东西南北上下左右前后][\d]+[米千公里]+`
- 剩余部分作为核心词对比

#### 4.1.5 每个地点的统计数据

| 数据项 | 来源 | 说明 |
|--------|------|------|
| 拍摄图片数量 | `COUNT(*)` 当前地点分组 | |
| 拍到的鸟种列表 | `DISTINCT object` 当前地点分组 | 数量多时（>5种）显示前5种 + "等" |
| 鸟种数量 | `COUNT(DISTINCT object)` | |
| 加新鸟种 | 对比当天之前的历史数据 | 当前地点首次出现的 `object`（不含 NULL/空）|

**加新判定逻辑**：

```sql
-- 查找当天某地点的鸟种中，哪些是之前从未拍到过的
SELECT DISTINCT br_today.object
FROM bird_results br_today
WHERE DATE(br_today.shot_time) = :target_date
  AND br_today.object IS NOT NULL AND br_today.object != ''
  AND br_today.object NOT IN (
    SELECT DISTINCT object FROM bird_results
    WHERE DATE(shot_time) < :target_date
      AND object IS NOT NULL AND object != ''
  )
```

#### 4.1.6 最佳照片

如果当天照片经过了对焦检测（`focus_detect_json` 非空），选取**对焦检测分数最高**的照片：

**分数取值优先级**：
1. `focus_detect_json` → 解析 JSON → `norm_score`（归一化分数，更稳定）
2. 若 `norm_score` 不可用，取 `score`（原始拉普拉斯方差）
3. 若均不可用，该天不显示"最佳照片"段落

**显示内容**：

```
🏆 今天拍到的最好的是{物种名}
   光圈 f/{fnumber}, 快门 {shutter}, ISO {iso}, 焦距 {focal_length}, 对焦距离 {focus_distance}
   [照片缩略图]
```

- 每个 EXIF 字段仅在数据库中有值时显示，无值则跳过
- 物种名取 `object` 字段，为空时显示"未知鸟种"
- 照片使用缩略图显示（复用现有缓存系统），点击可打开大图预览

#### 4.3.1 存储目录

```

### 4.4 日记自动生成

#### 4.4.1 首次启动

```
软件启动
→ MainWindow 初始化完成
→ 检查 bird_diary/diaries/ 目录是否为空
→ if 空（从未生成过日记）:
     启动后台线程 DiaryGenerateWorker
     → 查询 bird_results 所有有 shot_time 的记录
     → 按日期分组
     → 逐日生成日记 JSON 文件
     → 生成期间日记页面显示 "正在生成日记中..." 的占位界面
     → 完成后发送信号 → 日记页面刷新
→ else:
     日记页面直接加载已有日记
```

#### 4.4.2 增量更新

```
ImportPage 发出 import_to_library_succeeded 信号
→ MainWindow 转发给 BirdDiaryPage
→ 查询新导入照片的 shot_time 涉及哪些日期
→ 仅重新生成这些日期的日记（跳过已手动修改的日记，除非用户确认覆盖）
```

#### 4.4.3 手动修改保护

- 用户手动修改过的日记保存到 `modified/` 目录
- 增量更新时检测到 `modified/{date}.json` 存在 → 跳过该日期的自动重新生成
- 用户可在右键菜单中选择"重新生成"来覆盖手动修改

#### 4.4.4 关闭生成

在设置页面 `SettingsPage` 的「常规设置 → 基础选项」分组中新增：

```
☑ 自动生成拍鸟日记
```

- 对应设置键：`diary/auto_generate`，默认 `true`
- 取消勾选后：
  - 停止首次全量生成（如果正在进行）
  - 停止增量更新
  - 已有日记不删除，仍可查看和编辑
  - 侧边栏日记按钮仍可见（用户仍可查看已有日记和手动创建）

### 4.7 虚拟滚动

#### 4.7.1 设计思路

日记可能跨越数月甚至数年，日记数量可能达到数百篇，需要虚拟滚动保证性能。

**方案**：使用 `QScrollArea` + 自定义虚拟化容器：

- 维护所有日记的元数据列表（日期、预估高度），不预先创建 Widget
- 可视区域 ± 2 屏范围内的日记创建实际 `DiaryCardWidget`
- 超出范围的 Widget 回收到对象池（不销毁，清空内容后重用）
- 滚动事件中计算可视范围，按需创建/回收

#### 4.7.2 预加载策略

| 区域 | 策略 |
|------|------|
| 可视区域 | 完整渲染（文字 + 照片缩略图） |
| 可视区域 ± 1 屏 | 预渲染文字，照片异步加载 |
| 可视区域 ± 2 屏 | 仅创建 Widget 骨架，数据懒填充 |
| 超出 ± 2 屏 | Widget 回收，仅保留元数据 |

def _apply_background(self):
    bg_image = SettingsManager().get("diary/background_image", "")
    bg_color = SettingsManager().get("diary/background_color", "")
    bg_mode = SettingsManager().get("diary/background_mode", "cover")
    
    if bg_image and os.path.isfile(bg_image):
        # 使用背景图片
        if bg_mode == "tile":
            self.scroll_area.setStyleSheet(f'background: url("{bg_image}") repeat;')
        elif bg_mode == "stretch":
            self.scroll_area.setStyleSheet(
                f'background: url("{bg_image}") no-repeat; background-size: 100% 100%;')
        else:  # cover
            # QPainter 绘制等比裁切铺满（CSS background-size: cover 在 Qt 中有限，用 paintEvent 实现）
            self._bg_pixmap = QPixmap(bg_image)
    elif bg_color:
        self.scroll_area.setStyleSheet(f'background-color: {bg_color};')
    else:
        # 跟随主题
        dark_bg = ColorManager.instance().get("theme.background.dark")
        self.scroll_area.setStyleSheet(f'background-color: {dark_bg};')

def _apply_paper_style(self, card: BirdDiaryCard):
    paper_color = SettingsManager().get("diary/paper_color", "")
    paper_opacity = float(SettingsManager().get("diary/paper_opacity", 1.0))
    
    if not paper_color:
        paper_color = ColorManager.instance().get("theme.background.light")
    
    # 应用纸张颜色和透明度
    color = QColor(paper_color)
    color.setAlphaF(paper_opacity)
    card.setStyleSheet(f'''
        background-color: rgba({color.red()}, {color.green()}, {color.blue()}, {color.alphaF()});
        border-radius: 8px;
    ''')
```

## 7. 性能考量

| 场景 | 策略 |
|------|------|
| 大量日记（数百篇） | 虚拟滚动，可视区 ± 2 屏外的 Widget 回收池化 |
| 首次全量生成 | 后台 `QThread` 执行，生成过程中显示占位界面，不阻塞 UI |
| 照片缩略图加载 | 复用现有 `cache/` 缓存系统，异步加载 |
| 加新判定 | 全量生成时一次性查询历史物种集合并递增维护，避免每天重复查库 |
| 地点聚合 | 经纬度距离计算使用 Haversine 简化公式，文本相似度避免复杂 NLP |
| 时间导航渲染 | 仪表盘柱状图使用 `QPainter` 自绘，轻量高效 |

## 10. 风险与限制

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 无 `shot_time` 的照片 | 无法生成日记 | 提示用户通过轨迹匹配补充时间，或标记为"未知日期" |
| 无 `location` 的照片 | 地点信息缺失 | 显示"未知地点"，仍统计鸟种等数据 |
| 地点聚合误判 | 不同地点被合并 / 相同地点未合并 | 经纬度优先 + 文本兜底双保险；阈值可调 |
| 无对焦检测数据 | 无"最佳照片"段 | 条件段落自动隐藏，不影响其他内容 |
| `python-docx` 未安装 | Word 导出不可用 | `try-import` 检测，不可用时灰化菜单项 |
| 日记量极大（>1000篇） | 全量生成耗时 | 进度信号 + 后台线程，生成完成后通知 |
