# 拍鸟地图功能 —— 需求设计文档

> 版本: v1.0  
> 日期: 2026-03-24  
> 状态: 需求设计阶段

---

## 1. 功能概述

**拍鸟地图** 是一个可视化编辑功能，允许用户将运动轨迹（GPX/KML/KMZ）叠加到地图图层上，结合照片拍摄时间自动将鸟类照片定位到轨迹对应位置，并通过丰富的编辑工具生成一张精美的观鸟地图图片（参照下方效果图）。

**参照效果**：卫星底图 + 运动轨迹线 + 鸟类照片圆形裁切 + 鸟名标注 + 统计文字 + 半透明蒙层 + 自定义画布比例，最终导出为 JPG 图片。

## 2. 功能入口

### 2.1 右键菜单入口（带图片创建）

| 页面 | 触发方式 | 菜单项 |
|------|---------|--------|

**行为**：点击后打开拍鸟地图编辑页面（全屏覆盖，类似现有 `UpdatePage` 的栈页模式），传入选中图片路径列表和数据库表名，进入新建地图模式。

## 4. 核心功能模块

### 4.1 轨迹加载与照片匹配

#### 4.1.1 复用现有轨迹匹配逻辑

直接复用 `ui/widgets/track_match_dialog.py` 中的以下模块函数和数据类：

| 复用项 | 源位置 | 用途 |
|--------|--------|------|
| `TrackPoint` dataclass | `track_match_dialog.py:47` | 轨迹点数据结构 |
| `PhotoItem` dataclass | `track_match_dialog.py:54` | 照片匹配数据结构 |
| `_load_track_points()` | `track_match_dialog.py` | 解析 GPX/KML/KMZ 文件 |
| `_load_photo_items()` | `track_match_dialog.py` | 从数据库加载照片信息 |
| `_bisect_left()` | `track_match_dialog.py` | 二分查找 |
| `_parse_iso_to_ts()` | `track_match_dialog.py` | ISO 时间解析 |
| `_parse_photo_time_to_ts()` | `track_match_dialog.py` | 照片时间解析 |

**重构建议**：将上述模块函数和数据类提取到独立模块 `utils/track/track_utils.py`，使 `TrackMatchDialog` 和新的 `BirdMapPage` 均可引用，避免代码重复。

#### 4.1.2 匹配流程

```
用户选择图片 → 用户选择轨迹文件 → 解析轨迹点 → 照片拍摄时间匹配轨迹点（复用二分最近邻算法）
→ 超过最大容差（默认60秒）的照片标记为未匹配 → 匹配到的照片自动放置在地图对应坐标
```

### 4.2 轨迹编辑

#### 4.2.1 轨迹编辑模式

点击设置面板「轨迹编辑」按钮进入编辑模式，提供两种编辑方式：

**方式一：地图选点**
- 轨迹线上的点高亮可点击
- 点击轨迹点后弹出操作菜单：「设为起点」「设为终点」「删除此点之前/之后的轨迹」
- 支持框选一段轨迹进行删除
- 编辑后轨迹实时更新显示

**方式二：时间条选取**
- 编辑模式下底部弹出时间轴滑动条
- 时间轴显示轨迹的时间范围（起始时间 ~ 结束时间）
- 双端滑块控制起点/终点时间
- 时间轴上显示照片的时间标记点
- 拖动滑块时地图上对应的轨迹段实时高亮

```
时间轴示意:
|----[====📷===📷====📷==========📷===]------|
起始                                        结束
     ↑起点滑块                    终点滑块↑
```

#### 4.2.2 轨迹编辑数据

编辑操作不修改原始轨迹文件，在内存中维护编辑后的轨迹点列表（`edited_track_points`），保存时写入设计文件。

### 4.3 轨迹显示样式

#### 4.3.1 样式属性

| 属性 | 类型 | 默认值 | 范围 |
|------|------|--------|------|
| 线条颜色 | Color | `#00FF00`（绿色） | 任意颜色 |
| 线条粗细 | int | 3 | 1-10 px |
| 虚线 | bool | false | - |
| 虚线间隔 | list[int] | [10, 5] | 实线长/间隔长 |
| 显示箭头 | bool | true | - |
| 箭头间隔 | int | 50 | 每隔 N 个点显示一个箭头 |

#### 4.3.2 实现方案

轨迹渲染在 MapLibre GL JS 层实现，通过 `QWebChannel` 传递样式参数：
- 线条：MapLibre `line` 图层，设置 `line-color`、`line-width`、`line-dasharray`
- 箭头：MapLibre `symbol` 图层，使用 `arrow` 图标沿轨迹方向旋转
- 样式变更时通过 JS Bridge 实时更新图层属性

### 4.4 图片显示与编辑

#### 4.4.1 图片显示模式

| 模式 | 说明 | 实现 |
|------|------|------|
| **原图比例** | 按照片原始宽高比显示缩略图 | 直接缩放 |
| **自动识别裁切** | 调用鸟类检测模型定位鸟的位置，自动裁切为圆形/指定边框形状 | 复用 `core/detectors/` 检测框 → 裁切 → 蒙版 |
| **手动裁切** | 用户手动框选照片中的区域，设置显示边框形状 | 弹出裁切工具 |

**支持的边框形状**：圆形、圆角矩形、矩形、六边形、心形

#### 4.4.2 图片交互

| 操作 | 说明 |

| **自动定位** | 加载后自动放置在匹配轨迹点的经纬度对应位置 |

| **缩放大小** | 选中图片后出现缩放手柄，拖拽手柄或使用编辑面板输入尺寸 |
| **批量选择** | 按住 Ctrl 多选 / 框选多张图片 |
| **层级调整** | 右键菜单：置顶 / 置底 / 上移 / 下移 |

#### 4.4.3 鸟名标注

| 属性 | 说明 | 默认值 |

### 4.5 蒙层系统

#### 4.5.1 蒙层属性

| 属性 | 说明 | 默认值 |
|------|------|--------|
| 启用 | bool | false |
| 颜色 | Color | `#000000` |
| 透明度 | float (0-1) | 0.5 |

#### 4.5.2 渲染层级

```
从下到上:
1. 地图瓦片（卫星影像/街道地图）
2. 蒙层（半透明覆盖）
3. 轨迹线 + 轨迹箭头
4. 图片 + 鸟名标注
5. 自定义文字
6. 黑色边框（画布比例裁切）
```

#### 4.5.3 实现方案

蒙层在 MapLibre 层实现，使用一个覆盖全屏的半透明 GeoJSON 多边形图层，层级设置在轨迹线图层之下。通过 JS Bridge 动态设置 `fill-color` 和 `fill-opacity`。

### 4.6 文字添加与编辑

#### 4.6.1 添加方式

点击右侧设置面板的「添加文字」按钮，在地图中央生成一个默认文字框，用户可双击编辑内容。

#### 4.6.2 文字属性

| 属性 | 说明 | 默认值 |
|------|------|--------|
| 内容 | 多行文字 | "双击编辑" |
| 字体 | 字体族（模仿水印对话框的字体选择） | 系统默认 |
| 颜色 | Color | `#FFFFFF` |
| 大小 | int (pt) | 24 |
| 加粗 | bool | false |
| 倾斜 | bool | false |
| 下划线 | bool | false |
| 透明度 | float (0-1) | 1.0 |

**字体选择实现**：复用 `WatermarkDialog` 中的 `_pick_font_file` 与 `WatermarkState.font_family` 逻辑，支持从系统字体列表选择或加载自定义字体文件（.ttf/.otf）。

#### 4.6.3 文字交互

| 操作 | 说明 |
|------|------|
| **拖拽移动** | 鼠标拖拽文字到任意位置 |
| **对齐线** | 拖拽时自动显示与其他文字/图片元素的对齐辅助线（水平中心、垂直中心、顶部、底部对齐） |
| **双击编辑** | 双击进入文字编辑模式 |
| **删除** | 选中后按 Delete 键或右键菜单删除 |

#### 4.6.4 对齐线系统

- 拖拽任何元素（文字/图片）时，遍历其他可见元素的边界
- 检测水平/垂直方向的对齐（允许 ±5px 吸附容差）
- 对齐线为蓝色虚线，对齐时产生吸附效果
- 支持：左对齐、右对齐、水平居中、顶对齐、底对齐、垂直居中

### 4.8 画布比例与导出

#### 4.8.1 画布比例

| 预设 | 比例 | 典型用途 |
|------|------|---------|
| 4:3 | 横版 | 通用 |
| 1:1 | 正方形 | 社交媒体 |
| 3:2 | 横版 | 摄影标准 |

#### 4.11.8 实现方案 — 混合录制架构

**方案选型背景**：

编辑态采用双层架构（JS 地图层 + Qt 画布层），动画导出需要将两层合并。经过对比分析，采用**混合录制方案**：预览和导出共用同一套动画驱动逻辑，JS 层负责地图和轨迹渲染（GPU 加速），Qt 层负责图片和文字动画渲染，ffmpeg 管道编码输出。

```
┌─ 动画驱动（Python QTimeLine）──────────────────────────────┐
│                                                             │
│  每帧 tick(t):                                              │
│                                                             │
│  ┌─────────────────────┐    ┌──────────────────────────┐   │
│  │  JS 层（MapLibre）   │    │  Qt 层（QGraphicsScene）  │   │
│  │                     │    │                          │   │
│  │  更新轨迹 GeoJSON    │    │  更新图片 opacity/scale  │   │
│  │  (仅已绘制部分)       │    │  更新图片 position       │   │
│  │  更新头部光标位置     │    │  更新文字 opacity        │   │
│  │  蒙层始终可见         │    │  缓动函数插值            │   │
│  │                     │    │                          │   │
│  │  → toDataURL()      │    │  → scene.render()        │   │
│  │    得到 map_frame    │    │    得到 qt_frame         │   │
│  └────────┬────────────┘    └────────────┬─────────────┘   │
│           │                              │                  │
│           └──────────┬───────────────────┘                  │
│                      ▼                                      │
│            QPainter 合成 (map_frame + qt_frame)             │
│                      │                                      │
│                      ▼                                      │
│            裁切画布区域 → raw pixels                         │
│                      │                                      │
│                      ▼                                      │
│            写入 ffmpeg stdin 管道 / GIF 帧                   │
└─────────────────────────────────────────────────────────────┘
```

**分层职责**：

| 层 | 渲染内容 | 渲染技术 | 为什么放在这层 |
|----|---------|---------|---------------|
| JS 层 | 地图瓦片、蒙层、轨迹线、轨迹箭头、头部光标 | MapLibre GL JS (WebGL GPU 加速) | MapLibre 原生支持 GeoJSON 动态更新，轨迹渐进绘制只需更新 `source.setData()`，性能极好 |
| Qt 层 | 图片(+鸟名)、文字、画布边框 | QGraphicsScene.render() + QPainter | 复用编辑态的 QGraphicsItem，动画通过 `setOpacity()`/`setScale()`/`setPos()` 实现，无需重复开发 |

**动画驱动（预览/导出共用）**：

```python
class BirdMapAnimator:
    """动画引擎，驱动预览播放和导出渲染"""
    
    def tick(self, t: float):
        """推进到时间 t，更新所有元素状态"""
        # 1. 轨迹进度
        track_progress = self._calc_track_progress(t)
        self._bridge.updateTrackProgress(track_progress)  # → JS
        
        # 2. 图片动画
        for photo in self._photos:
            if t >= photo.appear_time:
                anim_progress = min(1.0, (t - photo.appear_time) / self._anim_duration)
                eased = self._easing(anim_progress)
                photo.graphics_item.setOpacity(eased)      # 淡入
                photo.graphics_item.setScale(eased)         # 缩放
                photo.label_item.setOpacity(eased)
        
        # 3. 文字动画（轨迹结束后）
        if t >= self._track_end_time:
            text_progress = min(1.0, (t - self._track_end_time) / self._text_anim_duration)
            for text_item in self._text_items:
                text_item.setOpacity(self._easing(text_progress))
```

- **预览模式**：`QTimeLine` 按实时速率调用 `tick(t)`，两层各自刷新显示即可（无合成开销）
- **导出模式**：按帧率步进调用 `tick(t)`，每帧截取两层合成后写入编码器（精确控制时间，不受系统性能影响）

**离屏渲染（导出用）**：

- 创建一个不可见的 `QWebEnginePage`，设置为导出分辨率的 viewport
- 加载与编辑态相同的地图 HTML，同步视口参数（center, zoom, bearing, pitch）
- 每帧通过 `page.runJavaScript()` 驱动 JS 更新，通过回调获取完成信号
- 截取：`page.view().grab()` 或 JS 端 `map.getCanvas().toDataURL()` → Bridge 传回 Python

**动画插值（缓动函数）**：

```python
def ease_out_cubic(t: float) -> float:
    return 1 - (1 - t) ** 3

def ease_out_elastic(t: float) -> float:
    if t == 0 or t == 1: return t
    return 2 ** (-10 * t) * math.sin((t * 10 - 0.75) * (2 * math.pi / 3)) + 1

def ease_out_quad(t: float) -> float:
    return 1 - (1 - t) ** 2
```

| 动画类型 | 缓动函数 | 作用属性 |
|---------|---------|---------|
| 淡入 | `ease_out_cubic` | opacity: 0→1 |
| 弹出 | `ease_out_elastic` | scale: 0→1.2→1（弹性回弹） |
| 缩放 | `ease_out_quad` | scale: 0→1 |
| 滑入 | `ease_out_cubic` | position offset: Δ→0 |

**JS 端轨迹渐进绘制**：

```javascript
// 通过 Bridge 接收 Python 的 progress (0.0 ~ 1.0)
window.bpmSetTrackProgress = function(progress) {
    const totalPoints = window._fullTrackCoords.length;
    const endIdx = Math.floor(progress * (totalPoints - 1));
    const visibleCoords = window._fullTrackCoords.slice(0, endIdx + 1);
    
    // 更新 GeoJSON source，MapLibre 自动重绘
    map.getSource('track-line').setData({
        type: 'Feature',
        geometry: { type: 'LineString', coordinates: visibleCoords }
    });
    
    // 更新头部光标位置
    if (window._cursorVisible && visibleCoords.length > 0) {
        const head = visibleCoords[visibleCoords.length - 1];
        map.getSource('track-cursor').setData({
            type: 'Feature',
            geometry: { type: 'Point', coordinates: head }
        });
    }
};
```

**编码方案**：

| 格式 | 编码方式 | 实现 |
|------|---------|------|
| **MP4** | ffmpeg stdin 管道（推荐） | `subprocess.Popen(['ffmpeg', '-f', 'rawvideo', '-pix_fmt', 'bgra', '-s', f'{w}x{h}', '-r', str(fps), '-i', '-', '-c:v', 'libx264', '-preset', 'medium', '-crf', str(crf), '-pix_fmt', 'yuv420p', output_path], stdin=PIPE)` → 每帧 `proc.stdin.write(frame_bytes)` |
| **GIF** | ffmpeg stdin 管道 | 同上，输出改为 `.gif`，加 `-vf "fps={fps},split[s0][s1];[s0]palettegen[p];[s1][p]paletteuse"` 做调色板优化 |
| **MP4 备选** | OpenCV VideoWriter | `cv2.VideoWriter(path, cv2.VideoWriter_fourcc(*'mp4v'), fps, (w,h))` → `writer.write(frame_bgr)` |
| **GIF 备选** | Pillow | `frames[0].save(path, save_all=True, append_images=frames[1:], duration=1000//fps, loop=0)` |

ffmpeg 管道模式的优势：
- 原始像素直接流入编码器，无需逐帧写临时文件
- 1080p 30fps 可接近实时编码
- H.264 帧间压缩比 cv2 的 MPEG-4 Part 2 质量更高、体积更小
- GIF 调色板优化效果远优于 Pillow 的全局调色板

**ffmpeg 可用性处理**：
- 优先检测系统 PATH 中的 ffmpeg
- 未找到时回退到 OpenCV VideoWriter（MP4）/ Pillow（GIF）
- 设置页面提供 ffmpeg 路径配置项

### 5.1 渲染架构（双层渲染）

由于需要同时支持地图交互和自由元素编辑，采用**双层渲染**架构：

```
┌──────────────────────────┐
│   QGraphicsView (上层)    │  ← 图片、文字、蒙层遮罩、对齐线、选框
│   透明背景，叠加在地图上  │     纯 Qt 渲染，支持拖拽/缩放/编辑
├──────────────────────────┤
│   QWebEngineView (下层)   │  ← 地图瓦片 + 轨迹线 + 轨迹箭头
│   MapLibre GL JS         │     JS 渲染，通过 Bridge 通信
└──────────────────────────┘
```

**交互分发**：
- 地图操作（平移、缩放）：如果鼠标位置没有 QGraphicsItem 则事件穿透到 WebEngineView
- 元素操作（拖拽图片/文字）：QGraphicsView 层拦截处理
- 坐标同步：地图视口变化时通过 Bridge 通知 Qt 层更新元素位置（经纬度→屏幕坐标）

## 6. 交互流程

### 6.1 带图片创建新地图

```
用户在图库/导图页选中图片（1张或多张）
  → 右键 → 点击「拍鸟地图」
  → 打开 BirdMapPage（全屏栈页）
  → 直接进入编辑模式，图片预加载到待匹配列表
  → 用户点击「选择轨迹文件」选择 GPX/KML/KMZ
  → 系统自动匹配照片到轨迹点，在地图上渲染轨迹和照片
  → 用户调整：
      ├── 编辑轨迹（裁切起终点）
      ├── 调整图片位置/大小/显示模式
      ├── 设置蒙层
      ├── 添加文字
      └── 调整画布比例
  → 用户点击「保存」→ 保存为 JSON
  → 用户点击「导出」→ 导出 JPG / GIF / MP4
  → 用户点击「退出」→ 检查是否有未保存修改 → 返回来源页
```

### 6.2 空白进入（管理/编辑已有地图）

```
用户在图库/导图页 → 点击工具栏「拍鸟地图」按钮 或 空白区域右键「拍鸟地图」
  → 打开 BirdMapPage（全屏栈页）
  → 显示欢迎面板（见 2.4）：
      ├── 点击「新建空白地图」
      │     → 隐藏欢迎面板，进入空白编辑模式
      │     → 用户可通过设置面板「添加图片」选择图片
      │     → 用户可通过设置面板「选择轨迹文件」加载轨迹
      │     → 后续流程同 6.1
      │
      ├── 点击「打开已有地图」
      │     → 弹出文件浏览对话框（默认目录: bird_maps/）
      │     → 选择 JSON 设计文件 → 加载 → 恢复所有状态
      │     → 进入编辑模式（流程同 6.3）
      │
      └── 点击最近编辑列表中的某项
            → 直接加载对应设计文件 → 恢复所有状态 → 进入编辑
```

### 6.3 编辑已有地图

```
任意入口加载已保存的 JSON 设计文件
  → 恢复地图视口（center, zoom, style）
  → 恢复轨迹（若原始文件存在则重新解析并应用编辑裁切，否则使用保存的 edited_points）
  → 恢复所有图片位置/大小/显示模式/鸟名标注
  → 恢复蒙层设置
  → 恢复文字元素
  → 恢复动画参数
  → 恢复画布比例
  → 进入编辑模式，用户可继续修改
```

### 6.3 退出保护

```
用户点击「退出」或按 Esc
  → 检测 is_modified 标志
  → if 已修改且未保存:
       弹出 MessageBox:
         "当前设计已修改但未保存，是否保存后退出？"
         [保存并退出]  [不保存退出]  [取消]
  → else:
       直接退出
```

## 8. 性能考量

### 8.1 图片加载

- 缩略图使用现有 `cache/` 缓存系统，避免加载原图
- 鸟类检测裁切结果缓存到 `data/cache/bird_maps/crops/`
- 大量图片（>50张）时使用虚拟化列表或分页加载

### 8.2 地图渲染

- MapLibre GL JS 使用 WebGL 硬件加速
- 轨迹点数量大时（>10000点）进行降采样显示
- 瓦片通过已有的本地代理服务缓存

### 8.3 静态图导出优化

- 导出在独立 `QThread` 中执行，避免阻塞 UI
- 使用进度条显示导出进度
- 高分辨率导出时分块渲染

### 8.4 动画导出优化

- **JS 层**：轨迹渐进只需 `source.setData()` 更新 GeoJSON，MapLibre WebGL 渲染极快，单帧 < 5ms
- **Qt 层**：`setOpacity()`/`setScale()` 不触发完整重绘，`scene.render()` 仅绘制可见项
- **蒙层**：作为 MapLibre 图层常驻渲染，不额外占用 Qt 合成开销
- **编码管道**：ffmpeg stdin 管道模式，原始像素直接流入编码器，零临时文件 IO
- **帧间优化**：地图视口不变时，MapLibre 内部会跳过瓦片重解码，实际只重绘轨迹图层变化
- GIF 导出建议分辨率不超过 1080p，避免文件体积过大；使用 ffmpeg palettegen/paletteuse 双通道色彩优化
- 导出期间 UI 显示进度条（帧数/总帧数 + 百分比 + 预计剩余时间），支持用户取消（向 ffmpeg 发 SIGTERM + 删除不完整文件）

## 10. 风险与限制

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| QWebEngineView 不可用 | 无法显示地图 | 检测环境，不可用时提示并降级为纯 Qt 画布（无在线地图） |
| 鸟类检测模型未安装 | 自动裁切不可用 | 检测模型可用性，不可用时隐藏「自动识别裁切」选项 |
| 轨迹文件无时间信息 | 无法匹配照片 | 提示用户，允许手动放置照片 |
| 大量图片导出 OOM | 导出失败 | 分块渲染 + 内存监控 |
| 网络不可用 | 地图瓦片无法加载 | 使用缓存瓦片，提示网络状态 |
| 动画导出耗时长 | 用户等待 | 显示进度+预计剩余时间，支持取消 |
| GIF 文件过大 | 存储/分享不便 | 限制 GIF 分辨率上限，提示用户选 MP4 |
| OpenCV VideoWriter 编码不可用 | MP4 导出失败 | 检测编码器可用性，备选 ffmpeg 或提示安装 |
| 轨迹无时间信息 | 无法计算动画时序 | 退化为均匀时间分配（按轨迹点序号均分总时长） |
